# ADR-0001: 学術稿は監査契約で検証する

## Status

Accepted

## Context

学術稿の改稿では、文を自然に整える操作が、中心命題、説明対象、章順、概念の来歴、引用の役割、注、投稿テンプレートを崩すことがある。一般的な自然さlintだけでは、これらの不変条件を表せない。一方、段落や節の意味関係をルールだけで自動的に判定すると、誤検出を避けるための文章が新たな定型文になりうる。

## Decision

Suikoに`academic`レーンを加える。原稿の意味を自動で決めるのではなく、執筆者又は監査者が先に作る**監査契約**と照合する。監査契約はSuiko内のローカルな機械可読作業記録であり、学術理論や標準用語ではない。

契約は中心命題、説明対象、形式的RQの要否、維持する順序、用語のstatusと出典、固有名詞、段落第一文の順、章間接続、注の本文・注・不要の判定、著者文体プロファイル、OOXMLの可変範囲を明示的に記録する。CLIはそれらと、同じ書誌行における引用―参考文献対応、留保候補、Markdown/DOCX/PDF同期、テンプレートOOXML不変条件、Microsoft Word書き出し記録を検証する。`passed`は原稿監査、`delivery_ready`はPDF全頁の目視記録を含む提出可能状態を示す。

## Consequences

- 既存の`lint`、`outline`、`terms`は変更せず、一般文書の誤検出範囲を広げない。
- 段落・節の意味判断、注の分類、著者の実質判断は人が先に行い、CLIはその記録漏れと成果物不整合を検出する。
- Wordを生成・再組版する機能はSuikoに加えない。公式テンプレートを基礎にした文書作成とWord PDF出力はSkillの納品工程で実行する。
- 提出前には機械検証とは独立に、PDF全頁の画像目視を続ける。

## Alternatives considered

### 学術論文向けの禁止語リストを増やす

不採用。防御的留保や否定構文は文脈によって必要であり、単語の削除だけでは概念・論証・納品の失敗を防げない。

### 章間接続と引用妥当性を完全自動採点する

不採用。自動出力へ迎合する加筆を誘発し、著者の論理順序を変える危険がある。候補抽出と人の契約判断を分離する。
