# ADR-0003: 規則を「直し方の族」で整理し、全規則を既定で表示する

## Status

Accepted（2026-11-15）

## Context

2026-11-15に、natural-japanese（`840bd40`）・yomiyasu（3.0.0）とsuikoのlintを、生成180文書・注釈50件と人間95文書で照合した（suiko-evalの[実行比較](https://github.com/nwiizo/suiko-eval/blob/main/eval/competitive-review-2026-11-15.md)）。分かったことは3つある。

- 意味破綻型・過剰圧縮型は、3ツールの決定的な検査のどれでもほとんど指せない。指せるのはLLMによる確認（`suiko meaning`）だけである。
- natural-japaneseの範囲のある指摘は、suikoが生成文書で301/320、人間文書で2,684/3,035を同じ箇所で指す。
- yomiyasuの指摘は、suikoが生成文書で173/808しか指せない。欠けているのは、同じ文末の連続、箇所ごとの否定対比、広い読点、比喩として使う語（土台・体温・効く・入口）である。

一方、suikoの規則は約95あり、「既定」「実験」「読解負荷」「確度」が別々の配列で管理されている。実験規則は`--experimental`を付けないと出ないため、利用者とエージェントは指摘の一部しか見ていない。他のツールの規則を名前ごと足すと、同じ箇所に複数の規則が重なり、規則の数だけが増える。

## Decision

1. 規則を、出どころや「AIらしさ」ではなく、**直すときに書き手が決めること**で7つの族に分ける。意味・型・語・区切り・読解負荷・文書の傾向・照合。定義は[規則の族と必要な機能](../rule-families.md)に置く。
2. 規則の属性（族、確度、範囲が箇所か文書全体か、読解負荷か、評価中か）を一つの登録表で管理する。`capabilities --json`と各指摘のJSONが同じ表から族と確度を返す。
3. **全規則を既定で表示する。** `--experimental`は互換のため受け付けるだけにする。表示するかどうかではなく、確度（high・medium・low）と`first_fixes`で、先に直す指摘を示す。外す手段は`.suiko.toml`の`disabled_rules`と理由付きの個別許可に一本化する。
4. 他のツールにある性質は、**既存の族の中で一番近い規則を広げる**形で取り込む。規則を新設するのは、直し方が既存のどの規則とも違う場合だけにする。AI頻出語の一覧のような、直し方を示さない規則は作らない。
5. 一つの箇所には一つの指摘を出す。広げた規則が既存の規則を包む場合は、包まれる側を出さない。
6. 規則が既定の表示に値する条件を決める。範囲（または文書全体であること）、直し方、残す条件、正例と反例のテスト、生成文書と人間文書での1000字あたりの件数の記録。

## Consequences

- 利用者とSkillは、1回の`lint`で全部の候補を見る。指摘の数は増えるため、確度と族で読む順番を決める。Skillは全部の指摘を「直す」か「理由を付けて残す」に分ける。
- 旧版のbaselineと、`--experimental`なしを前提にした件数は変わる。baselineは作り直す。
- 人間文書の過半に付く規則（`repeated_sentence_lead`、`low_lexical_diversity_ttr`など）も出る。これらは確度lowで、文書の傾向として読む。数を減らしたい利用者は設定で外す。
- 語の一覧を増やす方法は取らない。語は、何を書けば直るかが同じ既存の規則（`abstract_metaphor`・`vague_sensory_term`・`technical_jargon_metaphor`）へ、文脈の条件と一緒に足す。
- 意味の族は、決定的な規則を増やしても検出率が上がらない。この族の改善は`meaning`の評価（TODO）で扱う。

## Alternatives considered

### 他のツールの規則を同じ名前で移植する

同じ箇所に`short_topic_comma`と`pause_comma`、`antithesis_repetition`と`negative_parallelism`が重なる。直し方が同じ指摘を二重に読むことになり、設定で外す対象も倍になる。

### 実験規則を残し、Skillだけ`--experimental`を付ける

利用者がCLIを直接使うときと、Skill経由のときで見える指摘が変わる。どの規則が出ているかを、オプションの有無で覚える必要が残る。

### 確度lowの規則を既定で隠す

「隠すかどうか」の線引きが、実験規則と同じ問題を作る。隠さずに順番で示し、外すのは設定に任せる。
