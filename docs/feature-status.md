## 文書群を検査する入口

| 必要な機能 | 状態と利用方法 |
|---|---|
| 利用できる機能の確認 | 実装済み。`capabilities --json`が実際のサブコマンド・規則・検査記録の版を返す。Skillも優先して参照する。配布物での確認はリリース時に行う |
| Gitの版との比較 | 実装済み。`compare --rev HEAD <files...>`でファイル・カテゴリ別に前後件数、解消・新規・継続を集計する。リネーム・追加・削除も区別する |
| 複数ファイルの集計 | 実装済み。`lint --summary json\|tsv`で自然さと読解負荷を分けて返す。既存の`lint --json`はそのまま使える |
| 最終稿・原文・資料の検査 | 実装済み。`check`が検査記録を保存し、`verify`が入力・設定・実行ファイルの変更を確認する |

コマンド、出力、制限は[文書群の検査](batch-review.md)と[検査記録](revision-checks.md)を参照。

## 検査する範囲を区別する

| 必要な機能 | 状態と利用方法 |
|---|---|
| 明示した範囲の除外 | 実装済み。`suiko:ignore-start/end`をlintと読解負荷で共用する。不正な対応は警告し、本文を黙って除外しない |
| はてな記法 | 実装済み。書籍・画像・目次・埋め込みの既知の記法を行内でも除外し、本文・キャプションを残す。`stats.masking`に件数を返す。実記事群での再測定は残る |
| 英文引用による文長の過大評価 | 実装済み。日本語を含まない一定長以上の英文引用を読解負荷の計測から除く。技術用語を含む日本語や訳は残す。複数行の引用などは対象外 |
| コマンド・識別子の太字ラベル | 実装済み。`/describe`、インラインコード、ASCII識別子のラベルを`bullet_bold_label`から外す |
| コード内のコメントの保護 | 実装済み。除外範囲内でも`diff`と`check`はコードの変化を検査する。読点だけの変更にも回帰テストを追加した |

## 文脈に応じた推敲

| 必要な機能 | 状態と利用方法 |
|---|---|
| 体験と機能説明の可能表現を区別する | 実装済み。過去の体験を示す手掛かりがある候補は`evaluative_ability_past`のinfoに分け、essayでは抑制する。過去形だけでは区別しない。実例の校正は残る |
| 縮約と可能動詞の候補 | 実装済み。安全な局所置換は`suggestion`、文脈の確認を要する可能動詞は`review_suggestion`へ分ける。どちらもCLIによる自動適用はしない |
| 主題と述語の関係 | 実験的に実装。techの`topic_predicate_mismatch`が、限定した語彙と述語の組を確認候補にする。一般的な構文誤りの判定ではない |
| 近接した述語句の反復 | 実験的に実装。techの`repeated_predicate_phrase`が名詞と述語・活用の組を照合し、両方の位置を示す |
| 誤字・文脈付きの誤用 | 実装済み。techの`word_usage`が「しずらい」「選択肢として上げる」等を指す。語彙追加と助詞の取り違えの評価は残る |
| 段落内の文体混在 | 実験的に実装。techの`paragraph_register_mixture`が段落内の少数の異なる文末を示す。エッセイへ適用しない |
| 同じ文末の反復 | 既存の実験的な`repeated_sentence_mode`と統計を使う。既定へ広げる根拠の評価は未完了 |
| 評価を担う「重要なのは」 | 実装済み。「以下の点です」等の空の予告はwarn、中身のある評価はinfo。出現だけで削除を促さない |

## 書式と読みやすさ

| 必要な機能 | 状態と利用方法 |
|---|---|
| 太字の表示 | 実装済み。CommonMarkのパーサーとUnicodeの句読点・記号分類を使う。複数候補・4連・入れ子・リンク・コード・`!?`・全角コロン・`%`等を確認する |
| 書式だけを直すコマンド | 実装済み。`fix --bold`でプレビューし、`--write`で保存する。コード・引用・リンク先・除外範囲を保護する |
| 書式変更によるdiffの誤検出 | 強調を文分割の前にマスクし、読点・空白だけの変更を否定対比の検査から除く。コード内の空白の変更は検出する。可能動詞の内容語照合も明示的な能力の文脈に限って行う |
| 必要な読点の維持 | 長文で唯一の読点、後続の別主語や連体修飾、太字の表示に必要な読点を守る。実例の再校正と読点別の影響出力は残る |
| 文長と閾値付近の出入り | 文長からMarkdownの区切り・リンク先・空白を除く。具体性スコアは両側の計測値と閾値との差を出力し、±0.01以内を境界付近として示す |
| 見出しの装飾 | 実装済み。techの`heading_emoji`をinfoで返す。正式な題名や本文の感情表現を一律に削らせない |
| コロン導入の安定性 | 実装済み。40字の制限を外し、文末の形態素と後続ブロックで判定する |
| 不可視文字・重複読点 | 実装済み。不可視文字の位置とコードポイント、連続読点の範囲を示す。diffも新たな連続読点を確認する。コード・引用の表記例を保護する |

## 著者の判断を残す

| 必要な機能 | 状態と利用方法 |
|---|---|
| 指定した過去記事の文体観測 | 実装済み。`style-profile`が文頭・文末・語彙の分布、敬体率、平均文長、出典とSHA-256を返す。別の記事への有用性は要評価 |
| 推敲判断の集計 | 実装済み。`suiko-eval feedback`で明示された採用・維持・保留・未確認・対応不能を集計する。自由記述から判断を推測しない。実際の判断記録を入力する工程は残る |

語句の一覧だけを増やすのではなく、表層・形態素・文脈・書式・編集判断を分けて実装する。形態素から確定できない意味の同一性や係り先を、自動的に正誤へ変換しない。
