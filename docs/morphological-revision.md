# 形態素で検出する表現と、文脈から判断する表現

Suikoは語句を一括置換せず、品詞・基本形・正規化表記・助詞から読み直す範囲を指す。
語彙は意味の関係ごとに増やし、検出条件と修正判断を分ける。通常の`lint`で候補を出し、
Skillは候補の有無にかかわらず本文・資料を読み、修正するか残すかを決める。

## 参考記事から得た区別

[todesking「スロップ表現100連発」](https://zenn.dev/todesking/articles/5bc43f449ecdf6)は、
主述や修飾を読んだときの意味の不整合と、圧縮によって読みが一つに定まらない表現を区別している。
また、奇妙な表現にも意図次第で効果があると述べる。これを、問題の種類を分けて読む手掛かりにした。
記事の全例を誤文や禁止表現とは扱わず、全文の辞書への登録もしない。

## 解析の分担

0.4.1では、語句を列挙していた「しずらい」を、動詞の連用形＋接尾辞「ずらい」の基本形で検出するよう変更した。「使いずらい」「やりずらかった」「読みずらい」に同じ条件を使い、「ずらす」や引用・コードは除く。候補は接尾辞の先頭だけを「づ」へ替え、過去形・連用形を保つ。

可能表現は、元の動詞の活用型から五段・一段の可能形の語幹を生成する処理をlintとdiffで共有する。diffは「取る＋こと＋が＋できる」という明示的な可能表現をそろえて内容語を比べる。「取れる」単独を常に能力とみなす処理にはしない。否定、時制、格助詞、対象・主体、引用やコードの照合は残す。使役や不規則活用をこの規則へ無理に当てはめない。

| 対象 | 形態素で扱う範囲 | 形態素だけでは決めないこと |
|---|---|---|
| 接尾辞の誤表記 | 動詞の連用形、隣接、接尾辞の基本形・活用を確認し、元の範囲へ候補を返す | 引用やサービス名として意図した表記 |
| 可能表現の縮約 | 明示された可能の句と動詞の活用型から比較用の形を作る | 単独の「取れる」が可能か自動詞か、受身と可能の語義 |
| 補助動詞・形式名詞 | 前後の品詞と活用を見てかな表記の候補を作る | 引用・指定表記・本来の動作との曖昧さ |
| 連用形名詞 | 名詞＋助詞「の」＋対象語＋助詞または句読点。活用途中や複合語の一部を除く | 正式語・定着した名詞か、文書内で定義された語か |
| 対象と動作の比喩 | 名詞群＋助詞＋直近の述語。基本形・正規化形で過去形や表記差を照合する | 比喩の必要性、実際の処理先や発生条件 |
| 感覚と述語 | 感覚の種類と格を限定し、味・温度などが視覚動詞の目的語になる型を指す | 共感覚・逆説・換喩の効果、現実の物理現象 |
| 省略や主述のねじれ | 短い句や名詞列など、限られた表面形を候補にする | 長距離の係り受け、ゼロ主語、省略された目的語、事実の不足 |
| 物・感覚・時間・性質の動作主 | 語の類（家具・光や音・時間・性質）と、その類が通常取らない動詞の組。連体節を飛ばした最初の述語まで | 意図した擬人化、熱源や物の種類などの知識 |
| 全称と例外 | 隣接する2文で、全称の述語と、その否定か反対語の表にある述語を「だけ」とともに照合する。2文目は逆接の接続詞で始まるか、「〜だけが」「〜だけは」で主語を限る | 別の述語の例外、「だけ」の後に別の主語が来る接続詞のない文、文章全体の事実関係 |
| 場面付きの直喩（実験） | 「名詞＋の＋よう」の直前の名詞句に動詞の連体節があるか | 比喩の対応の正誤、意図した文学的効果 |

形態素解析を一般的な係り受け解析と同一視しない。別の主語、目的語、動詞、接続助詞、
括弧が現れたら関係を持ち越さない。直後の否定・引用・名詞化・連体修飾も確認する。
受身・使役の意味役割や複雑な並列を完全には解析しないため、候補がないことは正しさの証明にならない。

次は、否定・時制・態を文全体ではなく述語ごとに照合し、読点を別主語・連体修飾・列挙・短い目的語の境界へ分類する。形態素が示すのは局所的な品詞と位置なので、掛かり先が複数ある例は保留にする。読点の採否は削除前後の読解負荷とも照合する。太字・リンクはMarkdownのパーサー、重複読点・不可視文字は表層検出、事実や省略の補完は原文と資料の読み合わせへ分ける。

## 語彙と検出条件の構造

[`revision_lexicon.rs`](../src/lint/revision_lexicon.rs)は、対象名詞、助詞、述語、間に許す目的語、
確認する意味を一組にして持つ。時間の損失、処理の移動、道具の知識・願望・役目、潜在的な問題を扱う。
[`revision.rs`](../src/lint/revision.rs)はこの組を形態素列へ照合し、元の範囲を返す。
文脈に依存する候補には自動置換を付けない。固定された短句は正規表現、表記は専用の品詞判定を使う。
既存の技術表現の検査で扱える型は、重複した正規表現を増やさず既存処理へ寄せる。

かな表記が必ず同じ正規化形になるわけではないため、実際の辞書出力を確認する。
たとえば「ライブラリ」は「ライブラリー」へ正規化されるが、「とかす」は「溶かす」にならない。
前者は正規化形を辞書へ登録し、後者は必要な異表記として明示する。

語彙を増やすときは、検出する例だけでなく、本来の動作・別の節・否定・引用・複合語の例も加える。
同じ語の出現数を品質指標にしない。

## 回帰例

| 入力 | 期待する動作 |
|---|---|
| 調査に連休を溶かした。 | 時間の損失感を読む候補。後悔が伝わればSkillは残す |
| 休日を使って金属を溶かす。 | 最初の動詞で区切り、休日と溶かすを結び付けない |
| ジョブを別のキューに逃がした。 | 対象と移動の候補。非同期化などの仕様を補わない |
| この関数は事情を知らない。 | 否定された動作を肯定の擬人化として指さない |
| 甘さを眺める。／甘さの違う菓子を眺める。 | 前者を確認候補にし、後者では菓子が目的語なので除く |

[`tests/revision_morphology.rs`](../tests/revision_morphology.rs)で検出・除外・元の範囲・自動置換なしを確認する。
追加前には、語彙不足、感覚語不足、別の節への誤った結び付けの3テストが失敗した。
既存の既定動作・感覚語・技術表現のテストも合わせて検証する。

2026-10-30、Rust 1.97.1で全feature・全targetの200テストが成功した。
最後に追加した対話の語彙も含め、影響する4テストファイルの22テストを再実行して成功した。
Clippy（全feature・全target、警告をエラー扱い）、fmt、差分の空白検査も成功した。
Skill・説明文書のローカル参照はエラー0件だった。外部サイトへの接続確認はこの参照検査に含めない。

構造診断は変更前後で同じ範囲に実行した。`similarity-rs`は`src/lint`、テスト除外、
類似度0.90・最小10行で重複候補39組のまま。`cargo coupling`では`lint::morph`のスコアが
86から90になった。否定・引用の確認処理を感覚語・推敲・技術表現から共有する依存を確認し、
診断値だけを理由に別の抽象化は追加しなかった。
