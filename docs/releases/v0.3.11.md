# v0.3.11

公開前の原稿で読み直す箇所を見つけ、直すか残すかを判断してから再診断する手順を整えました。「日本語文書を決定的に診断し、自然で明晰な推敲を支援する」という方針のもと、表現と表記の確認候補を6種類追加し、技術文書の比喩と選択の方向を表す言い回しの検出範囲を広げています。

## 追加した診断

いずれも全ジャンルで `--experimental` を付けたときに有効になり、重要度 `info` で返します。

- `decision_direction_metaphor`: 「残さない側に倒す」など、選択を方向で表す箇所を検出します。何を残す・除外するのか、条件と動作を直接書けるかを確認します。
- `short_object_comma`: 文頭の短い名詞句と「を」の直後にある読点を検出します。読点を外して読み比べ、後続の述語とのつながりを確認します。
- `mixed_latin_spacing`: 同じ英数字語と日本語の境界で、半角空白の有無が混在する箇所をまとめて返します。統一された表記は、空白あり・なしのどちらも許容します。
- `boilerplate_closing`: 本文の最後の文が「ぜひ参考にしてみてください」等の定型句だけの場合に確認を促します。具体的な対象のある依頼は除きます。
- `vague_sensory_term`: 「顧客の解像度を上げる」「腹落ちした」「肌感としては」「温度感を揃える」など、理解・根拠・関心の程度を感覚語で表す箇所を検出します。何が分かったのか、判断の材料は何かを書けるかを確認します。画面や写真の解像度は対象外です。
- `copy_fragment`: 「資料を、全員へ。」のように、短い句の後に読点で間を置き、述語を書かずに終える惹句の型を検出します。誰が何をするのかを、文の働きに合う述語まで書けるかを確認します。

既存の`technical_jargon_metaphor`（`--genre tech`）には、「テストが黙ってスキップされる」「データが静かに失われる」「そこで地味に効いてくるのが」「バグを一つずつ潰していく」などを加えました。`decision_direction_metaphor`は「共通側に倒す」のような方針を表す言い回しも対象にします。

いずれも自動修正は付きません。説明済みの比喩、強調に必要な読点、意図した標語は残せます。人間が書いた技術記事にも「腹落ち」「原因の解像度を上げる」といった用例があり、これらの指摘は文章をAIが書いたかどうかの判定には使えません。

```sh
suiko lint draft.md --genre tech --experimental --json
```

## 改稿の手順

README、CLIヘルプ、Agent Skillに、初回診断・文脈に基づく改稿・baselineによる比較の手順をまとめました。改稿ガイドの「意味の補完を読者へ押し付けていないか」では、共有済みの前提と説明不足の違い、選んだ理由や条件の残し方、根拠のない情報を補わない判断を扱います。

指摘が消えても、意味が改善したとは限りません。改稿後は原文と比べ、事実・条件・著者の判断が保たれているかを確かめます。

[yomiyasuとの比較](../../eval/competitive-review-2026-10-01.md)から、情報の脱落と根拠のない追加を分けて確認する手順も取り込みました。語尾を整えるときは、読者への依頼、機能の説明、自動動作の区別を保ちます。

## 形態素解析と辞書の更新

sudachi.rsの再配布crateをv0.6.11からv0.7.0へ更新し、埋め込み辞書をSudachiDict 20260723.1 coreのV1形式へ移行しました。ビルド時に公式wheelをZIPとして展開し、配布ファイルと辞書本体のSHA-256を検証します。Pythonの実行は不要で、実行時の辞書取得もありません。辞書のライセンス文書はソースcrateとバイナリの配布アーカイブへ同梱します。

## 更新時の注意

- JSONのフィールド形式、既存の設定、公開型は維持しています。新しいカテゴリは `--experimental` を有効にした場合に返り、`--fail-on info` の判定にも含まれます。
- v0.3.10以前のbaselineは、v0.3.11で作り直してください。
- ソースからビルドする場合、以前のV0辞書は使えません。新しい辞書を自動取得させるか、検証済みのV1辞書を指定してください。

## 検証範囲

Rust 1.97で160テスト、Clippy（警告をエラー扱い）、fmtが成功しました。形態素解析による追加2ルールは各15例で検出と除外を確認しています。実文書99件では、短い名詞句の読点を4件検出し、選択を方向で表す新ルールは0件でした。これらの件数は、改稿の効果やAIによる執筆を示すものではありません。

空白混在と定型的な締め言葉は、検出・除外条件、位置情報、設定、終了コード、baselineを6テストで確認しました。開発用79文書では空白混在を15文書・39件検出し、締め言葉は0件でした。Web本文の取り込み時に混ざった目次・参考タイトルも候補になるため、文脈による判断が必要です。一般的な誤検出率や改稿効果は未測定です。

感覚語と惹句の2ルールは各15例、技術文書の比喩は25例で検出と除外を確認しました。実文書99件では、感覚語を人間の技術記事3文書で3件検出し、惹句と拡張した言い回しは0件でした。yomiyasuの比較記録にある素のLLM出力では、「解像度が一段上がり」と、`--genre tech`で「静かに壊れ」を検出しました。箇条書きの中の「時間を溶かさずに」「共通側に倒します」は、形態素ルールが箇条書きを対象外とするため検出しません。「この線引きが、日々の開発に地味に効いてきます」も、技術対象の主語がないため対象外です。

辞書更新による既存カテゴリの件数差は、`no_chain` の142件から141件への変化だけでした。既存7種の閾値比較は、全候補値で件数と率が一致しています。
