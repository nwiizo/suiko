# v0.4.3

v0.4.2の次の公開版です。`lint`・`check`・`compare`が、評価中の規則も含めて全規則を既定で表示するようになりました。指摘が増えても読めるように、規則を7つの族に分け、各指摘に族と確度を付けています。項目ごとの変更は[CHANGELOG](../../CHANGELOG.md)にあります。

## 全規則を既定で表示する

- これまで`--experimental`を付けたときだけ出ていた評価中の規則が、既定で出ます。語彙の多様性、文頭や文型の反復、装飾や箇条書きの比率などの規則です。
- `--experimental`は互換のため受け付けますが、出力は変わりません。指定すると、不要になったことを標準エラーへ1行で伝えます。
- ライブラリの`lint::analyze(.., experimental)`の動作は変えていません。

経緯と判断は[ADR-0003](../adr/0003-rule-families-and-default-visibility.md)に記録しました。

## 規則の族と確度

規則を、直すときに書き手が決めることで7つに分けました。

| 族 | 書き手が決めること |
| --- | --- |
| 意味（`meaning`） | 精読したとき、何を指すかが一つに定まるか |
| 型（`pattern`） | 同じ形を続ける理由があるか |
| 語（`wording`） | その語の代わりに、動作・対象・根拠を直接書けるか |
| 区切り（`punctuation`） | 読点・記号・書式が、掛かり先や表示に必要か |
| 読解負荷（`reading_load`） | 一文を読み終えるまでに、読み手が何を保留するか |
| 文書の傾向（`profile`） | 文書全体のそろい方が、内容から来ているか |
| 照合（`consistency`） | 本文の数・条件・事実が、本文の中と資料とで食い違わないか |

- `lint --json`の各指摘が、族（`family`）と確度（`confidence`）を返します。読解負荷の指摘も同じです。
- `capabilities --json`の各規則が、族・確度・範囲（`scope`: 箇所か文書全体か）を返します。
- 評価中の規則はすべて確度lowです。確度highとmediumの指摘は、残す条件に当たらなければ直します。確度lowの指摘と文書の傾向は、該当箇所を読んで判断してください。

族の定義は[規則の族](../rule-families.md)にあります。

## 新しい規則と広げた規則

- `repeated_sentence_ending`: 同じ段落で、同じ文末（です・ます・でした・ました・である・だ・だろう・でしょう・ですね）が3文以上続く箇所を示します。指す範囲は3文目の文末で、連続1つにつき1件です。過去の「た」、「ません」、「のだ」は数えません。
- `negated_contrast`: 「AではなくB」「Aではない。Bだ。」を箇所ごとに示します。これに合わせて、`antithesis_repetition`は文書全体の要約になり、対応する行だけを返します。
- `short_subject_comma`: 15字以内の名詞句＋「が」の直後の読点を示します。`short_topic_comma`（は・も）と`short_object_comma`（を）も、文の最初の読点だけでなく、文の中のすべての読点を見るようになりました。
- `abstract_metaphor`は抽象的なものの「土台」「羅針盤」を、`vague_sensory_term`は言葉や組織の「体温」「熱量」を、`technical_jargon_metaphor`は仕組みやルールが「効いた」と処理の「入口」「窓口」を、新しく示します。

新しい3規則は、人間の文書にも多く付くので確度lowにしています。

## 更新時の注意

- 既定の出力に評価中の規則と新しい規則が加わるため、指摘の件数が増えます。`--fail-on info`を使うCIは、新しく失敗することがあります。
- v0.4.2以前のbaselineは作り直してください。古いbaselineを指定すると実行エラーになり、作り直しを案内します。
- JSONの変更は追加だけです。
- 不要な規則は、`.suiko.toml`の`disabled_rules`か、理由を付けた個別の許可で外せます。
- v0.4.2のリリースには、macOSのバイナリが付いていません。GitHub Actionsが`macos-14`のランナーの提供を終えたためです。この版から`macos-15`で作ります。

## 内部の構成

大きくなったモジュール（`lint::morph`、`lint::metrics`、`cli`、`academic`、`diff`）を役割ごとに分けました。検出の動作と公開APIは変えていません。

## 検証範囲

Rust 1.97で、fmt、Clippy（警告をエラー扱い）、全テストが成功しました。suiko-evalでは、生成180文書と人間95文書で、新設・拡張した規則を測りました。

- `repeated_sentence_ending`は、yomiyasu 3.0.0の`sentence_end_repetition`が示した37件のすべてと同じ箇所を指しました。人間の文書では1000字あたり0.09件です。
- `negated_contrast`の1000字あたりの件数は、生成文書が人間の文書の3倍以上でした。
- 読点の3規則は生成文書で357件を示しました。従来の`short_topic_comma`は109件でした。
- 新設・拡張した8規則に、ラベル付き標本85件を足しました。この標本で正例はすべて検出し、反例の誤検知は1件でした。

確度と件数は規則の傾向を表すもので、個々の指摘が正しいかは本文で確かめてください。lintの指摘は、文章をAIが書いたかどうかの判定には使えません。測定の詳細は[suiko-evalの実行比較](https://github.com/nwiizo/suiko-eval/blob/main/eval/competitive-review-2026-11-15.md)にあります。
