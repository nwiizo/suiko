# Annotation guide

検出器と閾値の採否を判断するための人手評価の手順を固定する。目的は「Suikoの指摘に従うと文章が良くなるか」を測ることであり、著者がAIかどうかの判定精度ではない。

## 評価項目

1件のfindingについて、次の3つを**別々に**判定する。1つの総合点に潰さない。

1. **要修正**: この箇所は直すべきか（はい / いいえ / 判断不能）
2. **候補の自然さ**: 提示された修正候補（suggestionまたは推奨される言い換え）どおりに直すと自然になるか（はい / いいえ / 候補なし / 判断不能）
3. **意味と声の保持**: 直した結果、意味・事実・著者の声（意図的な反復、文体、ヘッジ）を損なわないか（保つ / 損なう / 判断不能）

## blind化

- 評価者には原文と修正文をラベルなしで提示し、どちらが機械の提案かを伏せる
- 提示順は評価集合の版から決定的に導出した順序で入れ替える（例: sample IDのハッシュ偶奇）。評価のたびに順序が変わる乱数は使わない
- 評価者は他の評価者の判断を見ずに独立して判定する

## 判断不能の条件

次の場合は無理に二値化せず「判断不能」を選び、理由を書く。

- 文脈（前後の段落、文書の目的、対象読者）がないと決められない
- 事実確認が必要（固有名詞、数値、引用）
- ジャンル規範に依存する（法令文体、翻訳の原文忠実性、意図的な修辞）

## 記録するもの

- 評価者ごとの判断と自由記述の理由（匿名ID可）
- 評価者属性: 日本語の執筆・編集経験の有無、対象ジャンルへの馴染み（記録はこの2点に限定し、個人を特定する情報は集めない）
- 評価日、評価集合の版（`corpus.toml`のSHA-256）、Suikoのバージョン

## 集計と報告

- 各サンプルは**2名以上**が独立評価する
- 百分率一致と、偶然一致を補正した一致度（Cohen's κなど）を項目別に報告する
- 率にはWilson 95%区間を併記する（`suiko-eval`の出力と同じ方法）
- **不一致は理由付きで残す**。機械的な多数決で「正解」を作らない。不一致自体が「意図的な反復」「文体差」のような正当な多様性を示している場合は、そのカテゴリの検出をinfo確認候補に留める根拠として扱う
- 再標本化の単位はfindingではなく**文書または著者**とする。同じ文書内のfindingは独立標本ではない

## dev / holdout

- `corpus.toml`の`split`フィールドで管理する（既定は`dev`）
- `holdout`はgenre・文書型・著者が`dev`と重ならないよう層化して作る
- `suiko-eval sweep`は`dev`だけを使う（実装で強制済み）。`holdout`は閾値を確定した後に一度だけ評価し、その結果で閾値を調整し直さない

## ルール変更の採用条件（事前登録）

点推定だけで採否を決めない。2026-08-18時点の条件:

| 変更の種類 | 最低標本数 | 条件 |
|---|---|---|
| 新カテゴリの追加（info） | fire/silent 各5件以上 | fpr のWilson上限 ≤ 0.30 |
| severityをwarn以上へ昇格 | fire/silent 各10件以上 | fpr のWilson上限 ≤ 0.10 |
| suggestionのallowlist追加 | 実コーパスでの出現10件以上 | 全件で意味・声を保つ（項目3が全員一致） |
| 既存カテゴリの閾値変更 | dev集合で従来比の差が説明できること | holdoutでの退行なし |

標本が足りない場合は変更を保留するか、info確認候補としてのみ導入する。`low_n`（分母5未満）の率は性能値として引用しない。

## ドメイン差の扱い

少数fixtureで選んだ閾値を別ジャンルへ一般化しない。genre・文書型ごとに発火率を分けて報告し、ジャンルをまたぐ結論には両方のジャンルの標本を要求する。
