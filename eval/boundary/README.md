# 一般校正との境界fixture

Suikoが受け持つ範囲と、既存の校正工程へ残す範囲を実行結果で固定する。各fixtureは一般校正で指摘されるべき問題を意図的に含み、Suikoの現在の挙動は`tests/compatibility.rs`の回帰テストで固定している（2026-08-18、sudachi.rs / SudachiDict core 20260723で測定）。

比較の原則: 発火しないことは検出漏れではなく、担当範囲の宣言である。Suikoは自然さ・構造・読解負荷に集中し、下表の問題を検出対象にしない。

| fixture | 含まれる問題 | Suikoの挙動(実測) | 分類 |
|---|---|---|---|
| `typo.md` | 誤字脱字（「次の分」「構築ずみ」） | finding 0件 | 既存ツールと併用（enno、textlint、商用校正） |
| `misuse.md` | 慣用句の誤用（役不足、敷居が高い、確信犯） | finding 0件 | 既存ツールと併用（Just Right!等の誤用辞書） |
| `variant.md` | 表記揺れ（サーバー/サーバ、行う/行なう、Web/ウェブ） | finding 0件 | 既存ツールと併用（prh、Vale vocabulary、textlint)。将来の`terms`用語監査で「揺れの一覧化」だけを扱う候補 |
| `keigo.md` | 二重敬語・誤った敬語（申されました、ご覧になられますか） | finding 0件 | 人間判断へ残す（機械判定の誤検知が多い領域） |
| `koyobun.md` | 公用文の表記（して下さい、有る、及び/並びに） | `translationese_morph` 1件のみ（「〜によることができる」がinfoの確認候補として発火） | 公用文ルールは既存ツールと併用。法令定型文での発火は`.suiko.toml`の理由付き許可で抑制できる |
| `risk.md` | 差別・リスク表現（片手落ち、外人、面接での家族構成質問） | finding 0件 | 人間判断へ残す（文脈と組織基準に依存。商用のD&I辞書が扱う領域） |

## オープンソース校正器との比較

2026-08-18に、textlint v15.8.0 + textlint-rule-preset-ja-technical-writing 12.0.2（既定設定）で同じ6fixtureを実行した。

| fixture | textlint (ja-technical-writing) |
|---|---|
| `typo.md` | 0件（誤字脱字は検出しない） |
| `misuse.md` | 0件（慣用句の誤用は検出しない） |
| `variant.md` | 0件（表記揺れはprh辞書なしでは検出しない） |
| `keigo.md` | 0件 |
| `koyobun.md` | 0件 |
| `risk.md` | 1件（だ・である/ですます混在のみ。リスク表現自体は検出しない） |

デファクトのOSS presetも一般校正6分類を検出せず、担当はスタイル規則（文長、文体混在、感嘆符、漢字連続）に留まる。「誤字脱字・誤用・表記揺れ・リスク表現は専用辞書（prh等）または商用サービスが担う」という上表の分類を裏付ける。なおSuikoの`kanji_run`（読解負荷）とtextlintの`max-kanji-continuous-len`は同種の観点を持つが、Suikoは固有名詞を除外する点が異なる。

## 運用

- これらの問題を検出する新ルールを追加する場合は、まずこのfixture群へpositive/negativeを追加し、十分な頻度と適合率を確認してから採用する（TODO.mdの採用基準）。
- 競合の非公開辞書を推測で複製しない。
- 規約上実行可能な商用サービスとの比較は未実施。実施時は入力データ、プラン、バージョン、実行日、設定をこのファイルへ記録する。
