# 学術稿と提出用文書の監査

この手順は、投稿論文、論文章、研究報告を執筆・改稿・納品するときに使う。ここでいう**監査契約**は、中心命題と成果物の不変条件を記録するSuiko内のローカルな作業記録であり、学術理論や標準用語ではない。

## 先に固定する事項

本文を直す前に、次を普通の言葉で一文ずつ記録する。

1. 説明又は分析の対象
2. 中心命題
3. ユーザーが決めた論理順序
4. 形式的なリサーチ・クエスチョンを置くかどうか
5. 既存語、出典固有語、著者の造語、導入しない語
6. 各節が受け取る命題と次節へ渡す必要

問いのない説明論文に、形式的RQを足さない。文章を整える都合で章順を変えたり、新概念を足したりしない。対象を説明してから名称を導入し、造語は造語と明示する。既存語は提示者又は出典と、その語が指す対象を示す。

## 文体と段落を監査する

著者の過去稿3〜5本から、接続詞の機能、文長、主語省略、段落内の文の役割、引用の位置、「〜とわかる」等の発見表現の置き方を記録する。語句や主張を模倣しない。文体見本は内容の根拠にしない。

各段落の第一文には、その段落が成立させる命題を置く。後続文を根拠、説明、具体例、条件又は帰結に分け、別の定義、方法、判定基準、結論を一段落へ詰め込まない。第一文だけを抜き出して、中心命題へ進む順が読めるか確認する。

節間では、見出しを隠し、前節末の本文命題と次節冒頭の本文命題を読む。共通対象、残余問題又は比較軸がなければ、接続詞だけを足さず、前節の到達点又は次節の必要性を本文に置く。

`XではなくY`、`必ずしも`、`可能性がある`、`対象に含めない`等は定型で付けない。成立条件は同じ命題に入れる。ユーザーが退けた案を、否定文として本文に残さない。

## 出典・用語・注を分ける

引用段落は著者名ではなく本文の主張から始め、出典をその根拠として使う。各中心引用では、出典の対象と射程、方法又は論理操作、具体的結果、原稿で担う役割を回収する。理論をつなぐときは、語の近さでなく、各理論が説明する対象、媒介、出力を区別する。

本文引用と参考文献はMarkdown見出しで欄を分ける。見出し両端の罫線・ダッシュ等の装飾は無視し、本文中の一般語は見出しとして扱わない。著者・年方式では、箇条書き・全角番号を除いた主著者・最初の出版年（`2024a`/`2024b`を区別）を双方向照合し、日本語の姓略記と姓名表記は同じ著者として扱う。引用キー方式では、本文の`[@citation-key]`と参考文献項目の`[@citation-key]`を双方向照合する。引用キー方式と著者・年方式は一つの原稿内で混ぜない。DOI・URL内の数字は出版年にしない。未引用文献と同じキーの重複を解消する。確認できない文献を補わない。注は、資料来歴、概念系譜、適用方法など本文の流れを止める補足だけに使う。論証を支える説明は本文へ置く。重複、留保、言い訳は削除する。

各注を`body`、`note`、`drop`へ分類し、その判断を契約へ記録する。分類は人が行う。Suikoは、注の未分類、本文の注番号と定義の対応、未使用定義、複数行注、本文との重複を検査する。

## 提出用DOCXとPDFを納品する

学会テンプレートを設計権威とする。白紙DOCXを再構築せず、公式テンプレートのOOXMLへ本文を反映する。Suikoは本文段落・表・図とその関係・メディアの**追加**を許す一方、`word/document.xml`の節設定（用紙、余白、段組、ページ罫線、ヘッダー／フッター参照）と、既存のヘッダー、スタイル、既存メディア及び既存関係の変更・削除を失敗として扱う。第一頁の罫線、余白、段組、フォント、表・図、注、参考文献を保つ。

最終PDFはMicrosoft Wordから出力する。LibreOfficeを提出用出力に使わない。出力後は、全頁を画像として目視し、頁数、罫線、段組、表図、注、参考文献、欠け、重なり、欄外へのはみ出しを確認する。

完成はファイル取得ではない。Markdown、DOCX、PDF、監査契約、テストが同期している状態を指す。同期はMarkdownリンク記法・脚注番号・表の罫線を除去した本文、表、注、参考文献の正規化ブロックを**順序非依存で双方向**に照合し、総文字量と重複ブロック数も比較する。Wordの脚注・文末注は`footnotes.xml`・`endnotes.xml`から取り込み、本文と注の格納順の違いは許す。成果物に残った旧文・重複文・余計な参考文献は失敗になる。`sync_omit_prefixes`はMarkdown側の意図的な除外ブロック、`sync_omit_fragments`は三成果物から同じ文字列を除く場合だけに使い、版型固有のヘッダー等も後者へ明示する。次のコマンドを実行し、契約違反を解消又は理由付きで判定する。

```sh
suiko academic paper.md --contract academic-contract.json \
  --docx submission.docx --template official-template.docx \
  --pdf submission.pdf --export-record delivery-record.json --json
```

`delivery-record.json`には`exporter: "Microsoft Word"`、`pdf_visual_reviewed: true`、Markdown/DOCX/PDFのSHA-256を記録する。前二者は納品者の**自己申告**であり、SuikoはWordから出力した事実や目視の実施事実を機械的に実証しない。`academic`のJSONで`passed: true`は指定された全チェックの合格である。提出完了にはDOCX、PDF、テンプレート、納品記録をそろえたうえで、`delivery_ready: true`を確認する。機械検証が通っても、PDF全頁の目視確認を省略しない。

```json
{
  "exporter": "Microsoft Word",
  "pdf_visual_reviewed": true,
  "source_sha256": "<MarkdownのSHA-256>",
  "docx_sha256": "<DOCXのSHA-256>",
  "pdf_sha256": "<PDFのSHA-256>"
}
```

## 契約の最小例

```json
{
  "version": 1,
  "central_claim": "本稿の中心命題をそのまま書く。",
  "explanandum": "説明対象をそのまま書く。",
  "allow_formal_research_question": false,
  "reject_defensive_caveats": true,
  "required_order": ["対象", "中心概念", "結論"],
  "terms": [
    {"term": "既存概念", "status": "established", "source": "提示者名"},
    {"term": "著者の名称", "status": "coined"}
  ],
  "proper_nouns": ["提示者名"],
  "accepted_labels": ["分類A", "公式値"],
  "first_sentence_order": ["導入段落の命題", "根拠段落の命題", "次節へ渡す命題"],
  "section_bridges": [
    {"from": "前節", "to": "次節", "shared_terms": ["共通対象"]}
  ],
  "note_decisions": [
    {"marker": "[^1]", "disposition": "note", "text": "資料来歴"}
  ],
  "style_profile": {
    "sentence_length_mean_min": 15.0,
    "sentence_length_mean_max": 80.0,
    "citation_led_paragraph_ratio_max": 0.5
  },
  "sync_omit_prefixes": ["版型固有のヘッダー"],
  "sync_omit_fragments": ["ページ番号"]
}
```

## 今後の拡張

- 引用と参考文献の著者名・年だけでなく、原典本文との命題対応を外部書誌DBなしで再現可能に照合する。
- Wordの変更履歴、コメント、頁別の視覚検査記録を納品記録へ取り込む。
- 著者文体プロファイルの観測値を、複数の承認済みBefore/After対とともに比較する。
