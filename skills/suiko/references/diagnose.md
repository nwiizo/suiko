# 診断モード（score）— 書き換えずに、AI臭さをスコアと理由で返す

診断モードは文書を一切書き換えない。返すのは3点だけ。スコアと、その根拠と、直すなら何からか。「この文章、AIっぽい？」「どれくらいAI臭いか採点して」という依頼に答えるためのモードで、リライトを求められたら通常の工程（SKILL.md §1〜5）へ切り替える。

## 3段階の深さ

診断の quick / full は、推敲のモード（SKILL.md「モードを選ぶ」）と同じ考え方の深さ指定である。書き換え工程がないぶん中身は次のように読み替える。食い違う場合はこの節に従う。

- **quick（既定）**: `suiko lint --json`（ジャンルが分かれば `--genre`）を1回と、スケルトンの一瞥。サブエージェントは使わない。30秒程度
- **full**: quick に加えて `suiko outline` / `suiko terms` を実行し、構造・読みやすさ・文書タイプの型（SKILL.md §1と§4の観点）を判断に織り込む。診断では直して再検査する往復をせず、1回の評価で完結する。数分
- **exp**: 互換のために残す指定で、full と同じ実行になる。v0.4.3から `suiko lint --json` が評価中の規則も既定で返すため、追加の実行はない

## スコアの算出 — 機械ベース + 判断調整の二層

スコアは0〜100の自然度で、**高いほど自然（AI臭が薄い）**。ユーザーへ返すときも向きを一言添える。二層で作り、内訳を必ず開示する。

**機械ベース（決定的）**: 100点から lint の `findings` を文書長で正規化して減点する。`reading_load`の指摘は数えない。

```
減点 = (critical×8 + warn×4 + info×0.5) × (1000 / max(文書の文字数, 1000))
機械ベース = max(100 − 減点, 20)
```

info は、各指摘の`confidence`がhighかmediumのものだけを数える。確度lowのinfoは、人間の文書にも多く付く規則（人間95文書の評価で、読点・同じ文末の連続・否定対比は3〜6割の文書に付いた）と、校正が済んでいない規則で、件数がAIらしさを表さないため減点に入れない。確度lowでもwarn・criticalは数える。v0.4.3から全規則が既定で出るため、数え方を変えないと、同じ文書のスコアが以前より下がる。数えなかった確度lowの指摘は、件数と代表箇所を「傾向」として理由に添え、判断調整の材料にする。この重み付けは目安で、コーパスでの校正はしていない。

文書の文字数は本文全体の文字数。改行・Markdown記法込みの len でよい（目安の正規化なので厳密さは要らない）。短い文書ほど1件の重みが大きく、長い文書は密度で効く設計になっている。本文が空か実質空（100字未満）の場合はスコアを出さず「診断対象として短すぎる」と返す。

**判断調整（±15点の範囲）**: full / exp では、構造レビュー・読みやすさレビューの所見で調整する。lint が拾えない構造のAI臭（全節同型、フラット列挙、確信度の平坦化、So What の空洞、順序・段階の押し付け）は減点し、lint が誤検知気味でも文脈上自然と判断した findings は減点を戻す。quick では調整せず機械ベースをそのまま使う（そのぶん「quick の精度は粗い」と明記して返す）。調整後の最終スコアは 0〜100 に切り詰める（min(max(スコア, 0), 100)。機械ベースが100で加点調整しても100を超えない）。

スコアは判断を含む目安であり、同じ文書でも数点は揺れる。CI のゲートに使う数値ではない。この注意は結果に一言添える。

## バンドと言い方

| スコア | バンド | 伝え方の例 |
|---|---|---|
| 90〜100 | 自然 | AI臭はほぼ見当たらない。指摘があっても好みの範囲 |
| 70〜89 | 軽微 | 数カ所に癖が残るが、読者が「AIっぽい」と感じる可能性は低い |
| 50〜69 | 要修正 | 表層か構造のどちらかに明確なAI臭がある。直す価値がある |
| 0〜49 | 濃厚 | 複数のカテゴリで強く検出。リライト推奨 |

## 出力の形式

1. **スコアとバンド**（機械ベースと判断調整の内訳つき）
2. **理由トップ3〜5**: カテゴリ名でなく中身で書く。「『〜ではなく』の対比が全文の4%で機械的なリズムになっている（L12ほか）」のように、代表箇所の行番号と、なぜそれがAI臭なのかを一言で
3. **直すなら何から**: 効果の大きい順に2〜3個。ただし診断モードでは直さない。「リライトしますか（quick/full）」と添えて終える

理由は lint の detail の転記ではなく、文書の文脈に即して言い直す。findings が多い場合も全部は列挙せず、スコアを最も動かしたものに絞る（フラット列挙はここでも避ける）。
