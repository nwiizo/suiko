# 依頼・返信・変更報告

メール、チャット、PR説明、障害連絡は、相手が必要な返答や確認をできるように整える。短くするために、依頼の強さ、期限、担当、未確認事項を変えない。

| 用途 | 残すもの | 見直すもの |
|---|---|---|
| メール・チャットの依頼 | 宛名、関係に合う挨拶・敬語、期限、実際の質問、原文の口調 | 依頼対象と期限の掛かり先が曖昧な文、同じお願いの重複 |
| PR・変更報告 | 変更した動作、変更の理由、検証結果、独立した変更点の箇条書き、識別子 | 「改善した」だけで変更点が読み取れない文、未実施の検証を実施済みにする書き換え |
| 障害連絡・調査経過 | 確認できた影響・時刻・復旧状況、未確認の原因、担当や次回連絡の約束 | 事実と推測が混ざる文、原文にない原因・通知先・期限の補足 |

## 直さずに残せる形

「先日お送りした見積もりはいかがでしたか」は具体的な質問なので、定型の締めという理由で消さない。「お手数ですが」も依頼の配慮として役割がある。チャットの「確認しておくね」を、媒体名だけを理由に「確認いたします」へ変えない。

PRの「期限切れキャッシュの削除を追加」は変更項目として読める。すべてを敬体の文へ展開する必要はない。「期限: 金曜日」「担当: 佐藤」のようなラベルは、値を探す用途で残せる。

## 根拠が足りない場合

「再試行の間隔を短くしました」から秒数は決められない。元と後の設定値が資料にあれば書けるが、推敲だけで測定値を作らない。「障害時に知らせます」に通知先や手段がなければ、特定のチームやメール通知へ書き換えない。

「見積書の送付と日程調整を金曜までにお願いします」の期限が両方に掛かるか不明な場合は、前後で確認する。決められなければその部分の意味を狭めず、本文とは別に質問を示す。ほかの箇所は先に仕上げられる。

## 仕上げ

原文と照らして、何をお願いしたか、何を実施したか、何が未確認かを確認する。報告に推奨や約束を足さない。相手が選べる依頼を必須の指示へ変えない。`diff`の指摘がなくても、この確認は省かない。
