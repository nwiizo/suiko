# 表現別の修正判断

標準の推敲で全文に使う。語の一覧は読み直す入口であり、一括置換表ではない。CLIに候補が出ない形、見出し・箇条書き・表・台詞も、それぞれの用途に合わせて読む。採否は[既定の推敲手順](revision-pass.md)の意味の照合で決める。

語が一覧にあるだけでは修正しない。個人の実感や後悔を伝える比喩が前後から読める場合は、
その人の言い方を残す。平易な動詞へ替えて出来事が同じでも、声や損失感が薄れることがある。
動作・条件を追えない説明と、意味が通じる体験の表現を分けて判断する。

## 読み直す問題と判断の分担

| 問題 | CLIで確かめる手掛かり | 本文と資料から判断すること |
|---|---|---|
| 誰が何をするか曖昧 | 名詞・助詞・直近の述語、基本形、否定と引用 | 主語・対象・条件を補える根拠があるか。省略を推測で埋めない |
| 感覚と動作の関係が不自然 | 感覚語と視覚動詞など、限られた組み合わせ | 実体と性質の混同か、意図した共感覚・換喩か |
| 短くまとめすぎて読みが定まらない | 助詞を省いた名詞列、連用形名詞、述語のない句 | 見出し・標語の役割か、本文で必要な関係が欠けているか |
| 判断や効果の中身が分からない | 評価語・専門語・比喩の候補 | 誰の判断か、何が変わるかが前後に説明されているか |
| 修正によって意味や声が変わる | 改稿前後の数量・否定・文末・対象の差分 | 原文の留保、許可、実感、後悔、文体を保っているか |

形態素の品詞・活用・隣接関係は、一般的な係り受けや事実の正しさを確定しない。
候補が出なくても主述と修飾を読む。候補が出ても、誤りや生成AI由来とは断定しない。

## 動作と比喩

| 表現 | 修正の方向 | 残す条件・変えてはいけない点 |
|---|---|---|
| 時間・休日を溶かす | 説明の対象や動作が読み取れない場合に、同じ意味で書けるか検討する | 本人の後悔・実感が伝わる「休日を溶かしてしまった」は残せる。「費やしてしまった」でも声が薄れるなら置換しない。氷・金属の動作は残す |
| 課題を潰す、処理を逃がす | 原文にある解消・移動・受け渡しの動作で書く | 何をどこへ渡すか不明なら、処理や相手を作らない |
| 地味に効く、効いてくる | 何が変わるかを、目立たなさ・徐々に変わる含みとともに書く | 「良い方向に働く」だけに置き換えない。薬の効果や定義済みの効果は残す |
| データが静かに壊れる、黙って捨てる | 気づけないことと、実際の状態・動作を区別する | 資料なしで「エラーを出さず」「整合性を失う」へ狭めない |
| 価格帯に収斂する、沈黙する | 落ち着く、反応しない等が同じ意味か確かめる | 終了・障害・通知の有無を推測しない |
| 動かしながら引き返す、経路が添える | 対象と動作の関係が資料にあれば、その関係を書く | 何へ戻るか・何を付けるか不明なら確認を分ける |
| 関数が事情を知る、DBと対話する、門番 | 入力・戻り値・呼び出し・条件を資料から説明する | 責務、依存、呼び出し、委譲などの定義語は残す |
| 土台、羅針盤、架け橋、武器、景色が変わる | 何を支え、何が変化するかを読む | 比喩の対応が説明済み、物理的用法、定着した慣用句なら残す |
| ジョブ・リクエスト・イベントを逃がす | 処理する場所や受け渡しを確認する | 「逃がす」を見ただけで非同期化・別プロセス・再試行へ置き換えない |
| モジュールが意図を知る、ライブラリが成功を願う | 参照する情報と処理の条件を読む | 成功を保証する動作に変えない。明示的な擬人化は残せる |
| 連休・休暇・一晩を溶かす | 時間の使い方と本人の感情を読む | 後悔や徒労感が伝われば残す。期間と損失感を弱めない |

「骨が折れる」「手を焼く」「首を長くして待つ」などの慣用句を型だけで直さない。小説・随筆の比喩は前後も読み、何を何に例えたか分かるなら残す。成り立たない比喩を、別の擬人化へ交換して済ませない。

## 感覚・実体・動作

語彙を感覚ごとに整理し、語単独ではなく述語との関係を読む。

| 語彙の群 | 読み直す組み合わせ | 自然な用法・修正の条件 |
|---|---|---|
| 音・雨音・足音・物音 | 音が窓や床を叩く | 音源が物へ当たったのか、音の強さの比喩かを区別する。音源を推測で追加しない |
| 匂い・香り・温もり・冷たさ・熱さ | 性質そのものを眺める・見つめる | 香りのする花や、温度計の目盛りを見る動作と区別する |
| 甘さ・苦み・酸味・渋み・塩味 | 味を視覚で捉える動作 | 味わう・確かめる動作、味を表す図を見る場面なら残す |
| 湿り気・手触り・柔らかさ・硬さ | 触感を視覚で捉える動作 | 見た目から質感を推測する描写は成立しうる。触った事実を作らない |
| 静けさ・静寂 | 静けさそのものが鳴る・響く | 逆説の効果が伝わるなら残す。静けさの中で鳴る物と混同しない |

同じ語があっても「甘さの違う菓子を眺める」は菓子を見る文である。
前の節の感覚語を、別の節の述語へ結び付けない。比喩の読みが一つに定まらない場合、
自然そうな物理現象へ書き換えるより、原文を残して不明な関係を短く示す。

## 名詞・専門語・直訳調

| 表現 | 判断 |
|---|---|
| 内容より大げさな文書名・管理用語、ゲート、台帳、境界 | 実際の方針・原文・確認・記録・対象範囲を、定義された役割のまま書く。正式名称や分野の意味は保つ。信頼性や唯一性を新しく足さない |
| 分離・保証・管理・対応・担保 | 動作と条件が資料にある場合だけ具体化する。保証の強さを落としたり、近い漢語へ替えただけで直ったと扱ったりしない |
| 旗、塊、腕などの直訳語 | プログラムのフラグ・ブロック、ロボットのアーム等だと対象が確定した場合に専門語へ戻す。身体、画面名、識別子は保つ |
| レベルの設定、案がテーブルにある | 適用範囲や未決状態を資料から明確にする。保存場所、担当、期限を推測しない |
| 見立て、潜む問題、招く混乱、欠かせない存在 | 判断した人、問題の中身、因果や必要性の理由が追えるか確認する。既に説明されていれば残す |
| 手触り、温度感、解像度、肌感、輪郭、地平 | 感覚そのものか、理解・合意・条件の比喩かを分け、説明に必要な中身を原文から開く |
| 腹落ち、正直なところ、良い感じ、強い設計 | どの評価・実感を担うか読む。実感を数値や別の比較尺度へ替えない |
| 結果の確かめ、案の比べ | 「結果を確かめる」「案の比較」など、対象と動作の対応を保つ。見直し、組み合わせ、資金集め、お選び、住民票の写しは残す |
| 候補の絞り、手順の見極め、条件のほどき | 対象と動作を保つ動詞の文にできるか読む。絞り込み、見直し、引き継ぎなど定着した名詞は機械的に開かない |
| パッケージ・モジュール・部署・チーム・ユーザー・アカウントのレベル | 適用対象の説明か、定義された階層名かを確かめる。保存場所や権限の継承を推測で補わない |
| 不具合・欠陥・落とし穴が潜む | 発生条件と影響が前後から追えるか読む。潜在的な可能性を、既に発生した障害へ変えない |
| 〜の実施、〜が可能、〜を図る、〜に資する | 自然な動詞へ戻せるか確認する。改稿で新しく硬くしない。規程・論文の正式語や能力の意味は残す |
| 活用、多角的、包括的、シームレス、シナジー | 内容が分かるときだけ、その使い方・観点・範囲・効果を書く。活用を単なる使用へ替えて「生かす」の意味を落とさない |

API表・スキーマのキー、型、enum、nullの扱い、必須性、数量、単位を保つ。専門語を直すだけで、判定条件が説明できたとは扱わない。説明不足を一般知識で埋めない。

## 評価・否定・定型表現

「重要なのは確認です」は「確認が重要です」とできるが、「確認します」では評価が消える。結論や方針への切替を示す前置きは、他の語で同じ関係を追えるときだけ省く。

「AではなくB」のAを消す前に、誤解や外れた仮説を訂正していないか読む。意味を担う否定は残し、Aを並列・目的・優先へ移さない。「Aではない。Bだ」は、同じ対比なら一文にできるが、後文が否定の理由ならまとめない。「弱みではなく、視点の違いでもある」は否定と「も」を一文のまま保つ。直前の二つを打ち消すだけなら「どちらでもない」と受けられるが、追加の限定・強調は落とさない。

否定だけで用語の説明を済ませている場合は、原文・資料にある肯定の定義を先に置き、誤解を防ぐ否定も残す。定義の資料がなければ作らない。

「と言えるでしょう」を縮めるときは推量を残す。分類に当たるかを評価している「〜に当たると言えるでしょう」は残す。「に他ならない」を「と思う」に弱めない。「もちろん、失敗もする」のような短い先回りだけの前置きは省けるか確認するが、返答・引用・前提の確認は残す。

予告・数の宣言・まとめ・定型の結び・チャット応答の名残は、読者への役割で判断する。実際の質問、提案、依頼、挨拶、次の予定は削らない。編集方針や作業報告が本文に残った場合は、本文の中身を残して作業の話だけを外す。範囲・対象読者・除外対象の説明は残せる。

## コピー調・読点・装飾

「資料を、全員へ」のような述語のない惹句、評価の短文の連続、他動詞だけの連用形の列挙、「必要なのは、A、B、C」の体言止めは、説明文なら主体・対象・時制が分かる述語へ戻す。見出し・標語・スライド・台詞・宣伝文では、その形の役割があれば残す。述語が不明な場合は補わない。

「丁寧な、人」のような修飾語と名詞の読点は、意味を分けるかを確認する。主題・目的語の直後でも、別の主語や修飾先を読み分ける読点は残す。動作や条件が切り替わる位置を見て、息継ぎの数で読点を増減しない。

説明を言い直すだけの括弧、不要なダッシュや文末コロンは整理する。ラベルと値のコロン、URL・コード、図の線、引用元の表示は保つ。「改善点: 応答が遅くなった」など説明を重ねるラベルは、区別を本文に残して整理する。「期限: 金曜」や用語・引数の説明は残す。

本文中の太字を残す場合は正しく表示させる。括弧だけを外側へ出す、句点を太字の外へ出す、難しければ文字に接する外側へ半角空白を置く。太字を増やす規則にはしない。原文の「■」「・」を用途の指定なしにMarkdownの見出しへ変えない。

宣伝文の勢い、台詞の間、随筆の一人称は削らない。数値・感情語・同じ語尾が多いだけで減らさない。一方、内容と釣り合わない誇張は評価の向きを保って見直し、事実としての順位・比較は根拠を確かめる。

## 表記

補助動詞の「実行して下さい」「確認して頂く」「試して見る」「指定出来ます」と、形式名詞の「する事」「する為」は、原文の活用と意味を保ってひらがなへ直す。「山の頂」「事の経緯」、本来の動作、引用・識別子・指定の表記は残す。

長音、送り仮名、漢字とかな、全角と半角、英字周囲の空白を、自然さの推敲だけで一律に統一しない。既存の表記指定があれば従う。明白な誤字・脱字は直すが、方言・固有名詞・人物の口調を誤字と決めない。
