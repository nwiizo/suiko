# 文書・読者・資料の扱い

標準の推敲で毎回使う。文書の用途は依頼と本文から判断し、書き手・読み手・関係は指定された情報を使う。不明な場合に設定を作って本文を変えない。

## 文書の用途

| 用途 | 修正で保つもの | とくに確認するもの |
|---|---|---|
| PR説明 | 独立した変更点・検証結果の箇条書き、識別子 | 何をどう変更したか。未実施の検証を実施済みにしない |
| 技術記事 | 因果・検証で外れた仮説・実際の動作・コード | 道具の擬人化を、資料にある入力・出力・処理で説明できるか |
| 障害報告 | 時系列、発生・復旧などの報告語、影響範囲 | 原因と推測、未確認、復旧済みと今後の対応を混同していないか |
| 提案書 | 提案、根拠、見込み、比較軸、制約 | 提案を決定事項へ変えず、想定効果に測定値を作らない |
| 議事録 | 議題、話者、決定・未決・担当・期限、ラベルと値 | 発言の帰属と決定状態。箇条書きを地の文へ戻さない |
| マニュアル | 手順の順序、番号、前提、警告、実行結果 | 誰が行う操作か。説明を指示に、任意を必須に変えない |
| スライド | 枚数・順序・見出し・まとめ・体言止め | 1行の見出しや箇条書きで、意味を分けない読点だけを整理。語句を無理に完全文にしない |
| 随筆・小説 | 観察、意図的な反復、読める比喩、間、気持ち | 自己解説や教訓を追加しない。成り立たない比喩も前後の説明を読んで判断 |
| 公用文・規程・仕様書 | 正式語、定義、条項・番号、義務・許可・権限 | 条件・例外の掛かり先。形式的な名詞化や「行う」を一律に口語化しない |
| 紹介記事・宣伝文 | キャッチコピー、褒め言葉、短文の重ね、感嘆符・絵文字 | 勢いを落とさず主述を整える。事実としての最上級や売上順位は根拠を確認 |
| メール・チャット | 宛名・署名・挨拶・気遣い、実際の質問、原文の口調 | 相手に依頼する内容と期限。原文にない謝罪・感謝・保証・約束を足さない |
| 論文・研究報告 | 専門用語、慎重な言い方、帰属、引用、正式な文体 | 主張と証拠の対応。長さだけで分割せず、学術稿の監査手順も使う |
| 台詞・脚本 | 話者・場面・順序・口調・方言・言いよどみ・ト書き | 明白な誤字とト書きの主述。台詞の句点は次の基準で扱う |

脚本では、台詞が10個以上あり半数以上が「。」で終わり、句点を残す指定がなければ、台詞末の「。」だけを外す案を検討する。途中の句点、ト書き、感嘆符・疑問符は残す。小説や引用へこの基準を広げない。音読教材や出版社の表記指定を優先する。

見出しの数・順序、指定されたまとめ、表の行・列・短いラベルは維持する。本文を探す助けになる見出しは定型でも残す。数字付き見出しを消して見出し数を変えたり、誇張を直すために見出しの主張を別物にしたりしない。

## 読者と書き手

同分野の専門家には、共有された用語へ毎回説明を付けない。分野外の実務者には、その分野固有の語が説明されているかを見る。専門知識のない人向けと指定された場合は、資料にある定義を添えるか言い換える。説明が資料にないときは、定義を創作しない。初心者を子ども扱いする語調や「簡単ですよ」などの評価も足さない。

用途の推定だけを理由に、敬体・常体、敬語、語の難しさを変更しない。読み手との関係や希望する語調が指定されている場合は、それに合わせて依頼の形を整える。相手の行為への尊敬語と、相手に向けた自分の行為の謙譲語を分け、二重敬語や不要な「させていただく」を作らない。人名・敬称・宛先は指定なしに変えない。

書き手が明示され、別の人の行為と読み違える箇所に限り、その書き手を主語に補える。担当者・経験・謝罪・感情は人物設定から作らない。チームの決定を個人の意思にしたり、一人称を機械的に削ったりもしない。随筆・宣伝文・台詞の声は保つ。

## 資料との照合

原文だけの推敲では、その文書と依頼を根拠にする。資料も渡された場合は、推敲の前後で次を確認する。新規執筆でも同じ確認を行う。

1. 本文の主張ごとに、根拠となる資料の箇所、対象、条件、時点を対応づける。
2. 数値・単位・名前・識別子・状態・担当・期限と、それが何を指すかを照合する。
3. 読者の判断に必要な抜けだけを、資料に明示された事実で補う。
4. 補った事実が新しい約束や因果になっていないか、資料と最終稿を読み比べる。
5. 根拠がない箇所は意味を狭めず残し、重要な点だけを本文の外で確認する。

「大幅に改善」「信頼性が向上」「短くしました」などで、何をどう変えたか分からない場合は、資料に対象や前後の値があるかを見る。実測値をすべて本文へ詰め込まず、判断に必要な分だけ使う。一般原則、書き手の実感、慎重な予測、意図的な余韻へ数値を要求しない。

正式な規程・仕様、論文、脚本では、追加の事実を本文へ入れること自体が内容の変更になる場合がある。推敲だけの依頼なら、補える事実は本文とは別に示す。資料に元の文の主語や用語の定義が明示され、関係を明確にするだけの修正は行える。

「昨日」「先週」は書いた日が確かに分かる場合だけ日付を添えられる。ファイル更新日から原稿の日付を推測しない。見聞きした日と、出来事が起きた日を区別する。随筆・宣伝文では日付の補足が不要な場合は残す。

仮置きの値は資料で確定できるときだけ埋める。伏せ字・テンプレート・例示は残す。「未定」「調査中」が原文にあることと、編集者に意味が分からないことを混ぜない。複数の資料が矛盾したら、都合のよい方を選んで確定しない。

用語の許可・指定があるプロジェクトでは、その方針を優先する。`.suiko.toml`の独自ルール・個別許可と、提供された用語集を利用する。用語の指定を守ることと、その用語の中身を説明せずに済ませることは別である。
